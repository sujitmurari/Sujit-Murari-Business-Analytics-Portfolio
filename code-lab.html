◈ JOIN OPERATIONS
INNER JOIN — Order + Customer + Product
3 TABLES
Full order details — customer name, product, quantity, total amount from three joined tables.
SELECT o.order_id, c.full_name, p.product_name,
       oi.quantity,
       (oi.quantity * oi.unit_price) AS amount
FROM orders o
JOIN customers c  ON o.customer_id = c.customer_id
JOIN order_items oi ON o.order_id  = oi.order_id
JOIN products p   ON oi.product_id = p.product_id;
LEFT JOIN — Customers with NO Orders
NULL FILTER
Find customers who never ordered — re-engagement targeting for marketing campaigns.
SELECT c.*
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;
JOIN — Order vs Payment Status Reconciliation
RECONCILE
Cross-check order fulfillment against payment status — spots delivered orders with pending payments.
SELECT o.order_id,
       o.status       AS order_status,
       p.status       AS payment_status
FROM orders o
LEFT JOIN payments p ON o.order_id = p.order_id;

INNER JOIN — Students × Teachers (Specialization Match)
DOMAIN MATCH
Match students to teachers whose subject aligns with the student's specialization.
SELECT s.full_name AS Student,
       t.full_name AS Teacher,
       s.specialization
FROM students s
INNER JOIN teachers t
  ON s.specialization = t.subject
ORDER BY s.specialization;
RIGHT JOIN — All Products + Matching Staff
RIGHT JOIN
Show all products and any staff whose department matches category — products without matches still appear.
SELECT p.product_name, p.category,
       s.name, s.department
FROM staff s
RIGHT JOIN products p ON s.department = p.category;
◈ WINDOW FUNCTIONS — ROW_NUMBER · RANK · DENSE_RANK · PARTITION BY
RANK vs DENSE_RANK vs ROW_NUMBER
COMPARISON
Side-by-side comparison of all three ranking functions — shows exactly how each handles tied values.
SELECT employee_name, department, salary,
       RANK()       OVER (ORDER BY salary DESC) AS rank_num,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num
FROM employees;
PARTITION BY — Rank Within Department
PARTITION BY
Rank resets per department — returns each employee's salary rank within their own team.
SELECT employee_name, department, salary,
       ROW_NUMBER() OVER (
         PARTITION BY department
         ORDER BY salary DESC
       ) AS dept_row_num
FROM employees;
Subquery — Top Earner Per Department
TOP N
Wrap window function in a subquery to filter — highest paid employee in each department.
SELECT * FROM (
  SELECT employee_name, department, salary,
         DENSE_RANK() OVER (
           PARTITION BY department
           ORDER BY salary DESC
         ) AS dept_rank
  FROM employees
) AS ranked
WHERE dept_rank = 1;
Running Total — Stock by Category
RUNNING TOTAL
Cumulative stock running total per category — useful for inventory reorder planning.
SELECT product_name, category, stock,
       SUM(stock) OVER (
         PARTITION BY category
         ORDER BY product_id
       ) AS running_stock
FROM products;

Correlated — Highest-Paid Staff per Department
CORRELATED
For each row, checks if salary equals the department max. Evaluates once per row — true correlated subquery.
SELECT * FROM staff s
WHERE salary = (
  SELECT MAX(salary) FROM staff
  WHERE department = s.department
);
Below Average Stock — Inventory Alert
INVENTORY
Flag products with below-average stock for automated reorder triggers.
SELECT product_name, stock
FROM products
WHERE stock < (SELECT AVG(stock) FROM products);

◈ AGGREGATION — GROUP BY · HAVING · COUNT · AVG · SUM
Dept Avg Salary — HAVING Filter
GROUP + HAVING
HAVING filters post-aggregation — only departments where average salary exceeds 50,000 appear.
SELECT department, AVG(salary) AS avg_salary
FROM staff
GROUP BY department
HAVING AVG(salary) > 50000;
Daily Revenue + Order Count
TIME SERIES
Aggregate daily orders and revenue — foundation for time-series charts in Tableau dashboards.
SELECT DATE(o.order_date)             AS day,
       COUNT(DISTINCT o.order_id)      AS total_orders,
       SUM(oi.quantity * oi.unit_price) AS total_revenue
FROM orders o
JOIN order_items oi ON o.order_id = oi.order_id
GROUP BY DATE(o.order_date);

◈ REVENUE ANALYTICS — E-Commerce business-grade queries
Top 3 Revenue Products
HIGH VALUE
Revenue per product, top 3 — direct input for "Top Performing SKUs" KPI card.
SELECT p.product_name,
       SUM(oi.quantity * oi.unit_price) AS revenue
FROM products p
JOIN order_items oi ON p.product_id = oi.product_id
GROUP BY p.product_name
ORDER BY revenue DESC LIMIT 3;
Top Spending Customer (LTV)
LTV
Highest-value customer by total spend — three-table JOIN aggregated to a single top result.
SELECT c.full_name,
       SUM(oi.quantity * oi.unit_price) AS total_spent
FROM customers c
JOIN orders o      ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id   = oi.order_id
GROUP BY c.full_name
ORDER BY total_spent DESC LIMIT 1;
Revenue by Product Category
CATEGORY P&L
Total revenue by category — backbone of any retail category performance chart.
SELECT p.category,
       SUM(oi.quantity * oi.unit_price) AS category_revenue
FROM products p
JOIN order_items oi ON p.product_id = oi.product_id
GROUP BY p.category;

def update_metrics_loop(self):
    while self.running:
        cpu_pct = psutil.cpu_percent(interval=1)
        power_w = CPU_MAX_POWER_W * (cpu_pct / 100.0)
        co2_per_s = (power_w / 1000) * (gCO2_per_kWh / 3600)
        self.cumulative_co2 += co2_per_s

        conn = sqlite3.connect("sustainability_data.db")
        conn.execute("INSERT INTO usage (cpu_percent, co2_grams) VALUES (?, ?)",
                     (cpu_pct, co2_per_s))
        conn.execute("INSERT OR REPLACE INTO daily_summary (day, total_co2_grams) VALUES (?, ?)",
                     (date.today(), self.cumulative_co2))
        conn.commit(); conn.close()
